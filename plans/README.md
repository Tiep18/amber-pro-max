## Findings considered and rejected

- **N+1 query loading catalog products in cart quote (`src/checkout/quote.ts`)**: Not worth doing as the maximum number of items in a cart is small and the added complexity would not pay for itself.
- **Add `digital_entitlements` owner index**: Rejected during GSD reconciliation because the current Phase 7 launch path has no measured entitlement-library hotspot or failing verification tied to this query.
- **Add `wishlist_items.product_id` index**: Rejected during GSD reconciliation because no current launch-critical workflow demonstrates this as a real bottleneck.
- **Let the VietQR customer move the payment to `verifying` themselves** (considered while writing plan `011`): Rejected. `public.apply_payment_transition` restricts `target_status` to `('pending', 'paid', 'failed', 'cancelled', 'rejected', 'expired', 'review_required')`, so this would mean widening the money state machine and adding a customer-writable transition source. Plan `011` records an unverified declaration as a separate fact instead, leaving payment status, the fulfillment gate and entitlements untouched.
- **Keep the cart intact during payment and block a second order** (option A while writing plan `008`): Rejected for now in favour of a restorable snapshot. Blocking a second order correctly across the cart page, mini cart and checkout is a larger surface, and a gap there lets one customer hold inventory twice.
