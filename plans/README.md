  health RPC's JSON payload was widened beyond the plan's example shape to

- **N+1 query loading catalog products in cart quote (`src/checkout/quote.ts`)**: Not worth doing as the maximum number of items in a cart is small and the added complexity would not pay for itself.
- **Add `digital_entitlements` owner index**: Rejected during GSD reconciliation because the current Phase 7 launch path has no measured entitlement-library hotspot or failing verification tied to this query.

- **Let the VietQR customer move the payment to `verifying` themselves** (considered while writing plan `011`): Rejected. `public.apply_payment_transition` restricts `target_status` to `('pending', 'paid', 'failed', 'cancelled', 'rejected', 'expired', 'review_required')`, so this would mean widening the money state machine and adding a customer-writable transition source. Blocking a second order correctly across the cart page, mini cart and checkout is a larger surface, and a gap there lets one customer hold inventory twice.
