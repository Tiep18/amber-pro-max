<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser address intent -> checkout server validation | All codes/names/mobile/address strings are forgeable and must be normalized/revalidated. |
| sessionStorage -> checkout UI | Stored PII intent is untrusted, tab-scoped, bounded, expiring, and never authority. |
| Browser save consent -> authenticated address RPC/RLS | Browser may request a save but cannot select identity or write the table directly. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T10-02 | Tampering | VN province/ward/mobile payload | mitigate (ASVS V5) | Strict Zod parse plus official pair/mobile normalization at final server submit and authenticated save boundaries. |
| T10-03 | Information Disclosure / Tampering | editable draft | mitigate (ASVS V3/V5) | Strict allowlist, 12-hour TTL, 16KiB cap, current-version-only read, malformed cleanup, forbidden-field source scan, and no PII logging. |
| T10-04 | Elevation of Privilege | save address | mitigate (ASVS authentication/access-control) | Server derives user, reuses existing RPC/RLS, accepts no caller user ID, and exposes no direct client table write. |
| T10-SC | Tampering | dependencies/schema | avoid | No package install, Supabase migration, generated type change, or RLS change is part of this plan. |
</threat_model>
