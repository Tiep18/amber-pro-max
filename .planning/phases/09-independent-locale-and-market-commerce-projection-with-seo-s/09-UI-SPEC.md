# Phase 09 — UI Design Contract

> Visual and interaction contract for independent locale and market commerce projection. Generated by gsd-ui-researcher for planning, execution, and UI verification.

---

## Intent

Phase 09 is a behavioral and state-safety refinement, not a storefront redesign. Preserve the current Ambertinybear layout, warm handmade palette, Nunito typography, compact header, product-card language, cart presentation, checkout composition, and existing shadcn primitives.

The UI must make language and shopping market visibly independent while ensuring that unresolved, failed, or stale commerce data can never appear purchasable. It must also replace complete market-sensitive result sets, keep cart and checkout quotes authoritative, and converge safely after rapid changes, focus recovery, or updates from another browser tab.

No market-specific public URL, new currency, new payment method, exchange-rate UI, broad navigation redesign, or new UI dependency is permitted in this phase.

### Continuity Rules

- Do not alter the global header height, container widths, product-card proportions, catalog grid breakpoints, product-detail hierarchy, cart two-column layout, or checkout information/summary layout except where a state region needs reserved space.
- Reuse current `8px` radii, one-pixel neutral borders, restrained shadows, and existing focus outline.
- Do not introduce nested cards, floating glass panels, new gradients, oversized pills, flags as the sole language/market labels, or animated currency transitions.
- Market and locale state changes must feel like updates to the existing storefront, not route-level redesigns.

## Surface and Responsive Contract

### Desktop Header (`md` and above)

- Preserve the current compact header footprint. Use one context trigger in the existing `HeaderMarket` position, with a `Globe2` icon and a concise committed summary such as `VI · VN` or `EN · INTL`.
- The trigger opens one existing `DropdownMenu`/popover containing two visibly separate, independently labeled choice groups:
  1. `Language`: `Tiếng Việt (VI)` and `English (EN)`.
  2. `Shopping region`: `Vietnam — VND` and `International — USD`.
- A divider separates the groups. Each group has one committed active item with `Check` plus `aria-checked="true"` or equivalent radio semantics.
- Below the market group, show one muted helper line: `Prices and availability only. Shipping destination is confirmed at checkout.` Localize it in Vietnamese.
- Selecting language navigates to the equivalent localized route and preserves the committed market. Selecting market keeps locale, equivalent route, and only the route-specific allowlisted query state.
- Do not render paired options such as `VN / VI` and `INTL / EN`; all four combinations must be selectable.
- Remove the legacy paired-choice switcher and the unused standalone market switcher as independent authorities. The header context control is canonical. A footer language-only control may remain as alternate navigation only when it uses the same equivalent-route logic, preserves market, and never implies that language changes currency.

### Mobile Header and Drawer (below `md`)

- Preserve the existing left `Sheet` navigation. Place context controls in the lower drawer region where the current combined context control appears.
- Render two full-width labeled fieldsets rather than a compressed combined dropdown:
  - `Language` uses a two-option segmented `ToggleGroup` or radio group.
  - `Shopping region` uses a two-row radio group so `Vietnam — VND` and `International — USD` remain fully readable at `320px`.
- Each option is at least `44px` high. Selected state uses accent text/check plus neutral selected background; unselected state remains readable without relying on opacity alone.
- The drawer remains open while a market action is pending or fails. It closes after a successful market commit or locale navigation.
- Context controls, account links, and safe-area padding must not overlap at `320px`–`390px` widths.

### Commerce Content

- Existing home, catalog, category, collection, product, wishlist, cart, and checkout layouts remain visually stable.
- Reserve fixed-height commerce state regions so resolving, ready, error, and retry states do not cause large layout shifts.
- At `375px`, no state label, currency, variant row, cart change summary, or retry action may create horizontal scrolling.
- Existing mobile sticky Add to Cart bar mirrors the main product-commerce state and respects `env(safe-area-inset-bottom)`.

## Storefront Context State Contract

The resolved storefront context is the only browser-level source for active browsing market. Its visible lifecycle is explicit.

| State | Visual contract | Interaction contract |
|-------|-----------------|----------------------|
| `resolving` | Context trigger shows neutral fixed-width loading text/skeleton; market-sensitive price, availability, variants, totals, and purchase controls use dimension-matched neutral placeholders | Disable all market-sensitive purchase actions. Keep localized content, navigation, images, and non-commerce prose usable. Announce `Checking prices and availability…` once through the shared polite live region |
| `ready` | Trigger and all commerce islands show the same committed market; VND only for `vn`, USD only for `intl` | Enable a purchase action only after context and the relevant projection agree on market, generation/version, product/variant identity, and offer fingerprint |
| `error` | Show an inline `Alert` in the affected commerce region; retain non-commerce content; do not show a current price or purchasable availability | Keep Add to Cart, checkout, and quote-dependent controls disabled. Provide `Try again`; retry creates a new generation and discards late responses |
| `retrying` | Reuse the same reserved region with `Checking again…`; no layout replacement or duplicate toast | Disable retry and purchase controls until success/failure; never run parallel retries for the same generation |

### No Misleading Currency Flash

- Initial indexable HTML may contain deterministic locale-default Product JSON-LD, but visible visitor-sensitive price, stock, variants, Add to Cart, cart totals, and payment UI render as non-actionable placeholders until private context and projection agree.
- Do not visibly render a Vietnam/VND offer and then replace it with International/USD, or the inverse, during initial hydration.
- During a market mutation, keep the old committed label and matching commerce UI until the server accepts the action. Immediately after commit, show the new label and mask old monetary/availability values with placeholders until the new projections and cart quote arrive.
- Never pair a new active-market label with old currency, old variants, or an enabled stale action, even for one render frame.
- Placeholder dimensions match the final price/CTA/variant region. A placeholder is `aria-hidden`; the shared text status communicates progress.

## Locale and Market Interaction Contract

### Locale Change

- Language is a navigation choice, not a commerce mutation.
- Preserve the active market and navigate to the equivalent localized path using the localized slug supplied for dynamic product/category/collection routes.
- Preserve only explicitly allowlisted query parameters for that route. Catalog may preserve `search`, `type`, `category`, `technique`, `tag`, and `sort`; auth may preserve a validated internal `next`; discard all other query state.
- The active market does not change merely because the target locale changes.
- After navigation, standard page focus behavior applies: the skip link remains first, and focus is not forced into the context control.

### Market Change: Pending, Commit, and Rollback

1. User selects a different market.
2. Keep the currently committed option checked. Mark the attempted option with a small pending indicator and expose `aria-busy="true"` on the market group.
3. Disable further market choices for the duration of the action, but do not disable the entire navigation.
4. Announce `Changing shopping region…` politely. Do not announce every card entering loading state.
5. On server success, commit only the server-returned market, close the desktop popover/mobile drawer, invalidate every market-sensitive projection, clear quote cache, requote the cart, and notify other tabs with an invalidation/version signal.
6. On failure, remove the pending marker, keep the prior option committed, keep the choice surface open, and show a localized inline error with `Try again`. Do not optimistically retain the failed label.

Rapid `VN → INTL → VN` input is latest-intent-wins. Abort or ignore older requests by generation. A late response must not move the checked option, currency, catalog, product variants, cart quote, or checkout method backward.

## Complete Catalog Projection Contract

This contract applies to homepage featured products, catalog, category, collection, technique/tag discovery within phase scope, wishlist hydration, and any shared product-card surface.

### Resolving and Loading

- Keep the static page heading, descriptive copy, search/filter/sort controls, and layout shell visible.
- The product grid region uses dimension-matched card skeletons. Facet labels/counts use skeleton rows. Do not leave locale-default products visibly presented as the active-market result.
- Mark the one result container `aria-busy="true"`; do not put live regions inside every product card.
- Search/filter/sort inputs preserve entered/query state while the context resolves. Fetch begins only when context is ready.

### Atomic Replacement

- A successful response replaces the complete product list and complete matching facet/count set in one state commit.
- Never overlay prices onto the SEO-default cards, merge old and new market arrays, or retain a facet count from a prior market/query.
- The result identity includes locale, resolved market, surface kind, normalized search/filter/sort state, and projection generation/version.
- Discard a response if any identity field differs from current state.
- Reset client `Load more` visible count to the first page after market or normalized filter identity changes. Preserve it only when the complete result identity is unchanged.
- Announce one concise result update: `International store loaded. 18 products.` / `Đã tải cửa hàng quốc tế. 18 sản phẩm.`

### Empty and Error

- Ready empty state replaces the grid region, not the page header or controls.
- Empty heading: `No products match this market and filters.`
- Empty body: `Change a filter or choose another shopping region to see more products.`
- Error heading: `We couldn’t update this store.`
- Error body: `Prices and availability may be out of date. Try again before shopping.`
- Error action: `Try again`. Do not restore stale cards as if current; if retained for visual continuity, they are inert, obscured from assistive technology, and explicitly labeled as previous results.

### Focus After Replacement

- Keep focus on the control that initiated search/filter/sort or market change.
- If a focused product/action disappears, move focus to the result heading (`tabIndex={-1}`) and announce the new count. Do not move focus for ordinary successful background refreshes.

## Product Offer and Variant Agreement

### Agreement Gate

The product commerce island becomes actionable only when all of the following match current state:

- Product ID and locale.
- Resolved browsing market.
- Current context generation/version.
- Projection market and projection identity/version.
- Selected variant exists, is enabled, is in stock, and belongs to the current projection.
- Offer fingerprint attached to the rendered action matches the current projection.

The fingerprint is a stale-UI guard only. Copy must never suggest that browser data is final order authority.

### Visual States

| State | Price / variants | Add to Cart |
|-------|------------------|-------------|
| Resolving projection | Price skeleton; variant rows use fixed-height skeletons or disabled neutral rows | Native disabled button retains final width; adjacent status reads `Checking availability…` |
| Ready and available | Show only active-market currency and valid variants; preserve current product-detail styling | Enabled with existing label `Add to cart` or `Buy and download` |
| Ready but variant required | Show valid variant choices; unavailable choices remain visible, disabled, and labeled `Out of stock` | Disabled until an enabled in-stock variant is selected; adjacent reason names the required action |
| Ready but unavailable in active market | No price that could imply purchase; warning surface names active market and, when available, the other market | Disabled; visible label remains stable and adjacent copy states `Unavailable in this shopping region` |
| Projection error | No current price; inline error in commerce region | Disabled; adjacent `We couldn’t confirm this offer. Try again.` plus retry action |
| Stale/mismatched response | Do not commit the response or change selection | Remains disabled until a matching response arrives |

- When a new projection removes or disables the selected variant, clear selection, keep the variant group focusable, announce `Your previous option is no longer available`, and keep Add to Cart disabled.
- The desktop main action and mobile sticky action must share the same agreement predicate and pending/error state.
- On accepted Add to Cart, write `marketAtAdd` from the resolved context used by the matching projection, then await the authoritative cart quote before showing a success state.
- While Add to Cart is submitting, disable both desktop and sticky copies, preserve button dimensions, and show `Adding…`; a failed quote does not show `Added to cart`.

## Cart and Checkout Preservation

### Market-Triggered Cart Requote

- A successful market commit clears the previous quote cache and starts one latest-request-wins authoritative cart requote.
- During requote, preserve product identity and quantity but replace monetary values and current eligibility with skeletons. Show `Updating cart for Vietnam…` or `Updating cart for International…` in a reserved `role="status"` region.
- Set `aria-busy="true"` on cart and mini-cart quote regions. Disable checkout and quote-dependent quantity/discount/payment actions until the current requote resolves. A safe explicit remove action may remain available if it cannot race the quote reducer.
- Never display `-`, zero, `Free`, old VND, or old USD as the new current total while requoting.
- On success, replace all line status, prices, discounts, shipping facts, currency, subtotal, and total together.
- On failure, preserve cart intent, show `We couldn’t refresh your cart. Try again before checkout.`, keep checkout disabled, and offer `Try again`.

### Cart Change Summary

- After requote, show one persistent warning/success summary above cart lines and inside the mini-cart summary when any material fact changed.
- Group changes under explicit labels: `Unavailable`, `Removed from current offer`, `Price changed`, `Currency changed`, and `Quantity adjusted`.
- Name each affected product/variant. For repricing, show previous → current value only when both values are valid in the same currency; for currency changes, show the old and new currency labels without implying FX conversion.
- Do not silently delete persisted cart intent. Unavailable/removed lines remain visible as blocked rows with an explicit `Remove` action.
- Checkout stays disabled while any line is unavailable or while the current quote is unresolved. Non-blocking repricing/currency summaries may be dismissed after review.
- Announce one summary sentence, not every line: `Cart updated. 2 items changed; 1 needs your attention.`

### Destination-Driven Material Change

- Once a physical destination exists, the accepted quote market is destination-derived; changing the header browsing market does not override it silently.
- Preserve the existing latest-request-wins destination quote lifecycle.
- A material destination change opens the existing modal pattern with a trapped focus and the title `Shipping and total changed`.
- Show explicit previous → proposed market, currency, shipping, line eligibility, discount, and total facts. Do not show a generic warning without the affected values.
- Primary action: `Use updated quote`. Secondary action: `Review destination`.
- Until accepted, checkout submission remains blocked and the prior quote is visually identified as previous, not current for the edited destination.
- `Review destination`, Escape, or overlay dismissal never accepts the proposal. Return focus to the first destination field responsible for the change.
- On acceptance, update line states, summary, allowed payment method, and total atomically. Render only VietQR for accepted `vn + VND`, and only PayPal for accepted `intl + USD`.

### Checkout Submission

- Disable order submission whenever storefront context, cart quote, destination quote, accepted material-change evidence, market/currency pair, or payment intent is unresolved or mismatched.
- Adjacent helper text names the blocker; a disabled control must never be the only explanation.
- Submit-time stale rejection returns to the quote status/change-summary region, preserves entered checkout data, focuses the error heading, and provides the appropriate requote/review action.

## Cross-Tab, Focus, and Navigation Convergence

- Cross-tab messages carry only invalidation/version information. Never trust or render a broadcast market, price, currency, cart quote, or projection body.
- A receiving tab enters `resolving`, masks market-sensitive values, disables purchase/checkout actions, refetches authoritative context, then refreshes projections and cart quote for the returned generation.
- Shared polite announcement: `Store preferences changed in another tab. Updating…`
- On `focus` or `visibilitychange` to visible, revalidate when the context freshness policy requires it. Do not flash a loader or mask content when the authoritative version is unchanged.
- If focus recovery finds a changed market, follow the same full invalidation/requote lifecycle as an explicit switch.
- If a local market action and cross-tab signal overlap, newest server-confirmed generation wins. Older completions are discarded without a toast.
- Background convergence never steals focus, scrolls the page, closes an unrelated dialog, or resets search/filter/form input. Only a blocking material-change dialog may intentionally move focus.
- Client navigation and browser refresh must never restore a quote cache whose market/context version differs from current resolved context.

## Accessibility Contract

- Desktop context popover uses two named radio groups or equivalent menu-radio semantics. Mobile uses two visible `fieldset`/`legend` groups. `Language` and `Shopping region` must not share one ambiguous label.
- The active locale uses `aria-current` or checked radio semantics. The active market uses checked radio semantics. Do not put `aria-current` on both dimensions as if market were navigation.
- Context trigger accessible name includes both committed values, for example `Language: English. Shopping region: Vietnam.`
- All visible labels and live-region messages are localized. Currency codes may remain standard `VND` and `USD`.
- One shared context live region uses `role="status"`, `aria-live="polite"`, and `aria-atomic="true"`. Blocking failures use `role="alert"`. Avoid nested or per-card live regions.
- Loading skeletons are `aria-hidden="true"`; their container exposes text status.
- Error messages remain adjacent to the affected control/commerce region and associate through `aria-describedby` where applicable.
- Retry returns focus to the retry action while pending and to the refreshed region heading only when content that held focus was removed.
- Material-change dialogs use `aria-modal="true"`, a labelled title and description, focus trap, Escape support, and focus restoration.
- All controls have visible focus and minimum `44px` touch targets. Disabled states retain enough contrast to be identifiable and include adjacent reason text.
- Respect `prefers-reduced-motion`. Use existing short opacity/color transitions only; no price counting, card shuffling animation, or motion-dependent status.
