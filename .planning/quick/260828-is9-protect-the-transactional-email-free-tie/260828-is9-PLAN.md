# Public Transactional Email Quota Guard Implementation Plan

> **For agentic workers:** Execute inline because this session does not authorize subagents. Follow test-driven development and verify each task before committing.

**Goal:** Prevent public email abuse from exhausting the transactional-email free tier without weakening guest privacy or adding paid infrastructure.

**Architecture:** Trusted Next.js server actions compute domain-separated keyed request identities. Narrow service-role PostgreSQL RPCs serialize rate-limit counters, derive authoritative subscriber/order facts, and enqueue only eligible email intents. The existing outbox claim RPC adds deterministic business priority.

**Tech Stack:** PostgreSQL/PLpgSQL, Supabase RPC/RLS, Next.js server actions, Node HMAC, TypeScript, Vitest, Node security tests, pgTAP.

**Spec:** `.planning/quick/260828-is9-protect-the-transactional-email-free-tie/260828-is9-CONTEXT.md`

## Global Constraints

- Preserve generic public responses for invalid, unknown, mismatched, and throttled requests.
- Store no raw IP in rate-limit or consent evidence.
- Do not trust browser-provided request hashes, order relationships, recipients, locale, or subscriber state.
- Add no Redis, paid queue, new provider, or external rate-limit service.
