# Summary

Added targeted, presentation-only loading skeletons for localized storefront, catalog, product, checkout, account, order, and admin route segments. The fallbacks preserve the existing layouts and avoid rendering guessed commerce, payment, inventory, entitlement, or fulfillment facts.

Added accurate pending feedback and duplicate/conflict protection for catalog navigation, checkout submission, PayPal refresh, sign-out, wishlist quick-add, address actions, protected downloads, guest-order claim, VietQR decisions, taxonomy deletion, and admin catalog filters. Checkout keeps its existing idempotency key and never automatically retries.

Reduced safe server waterfalls by memoizing the verified authenticated user per React request, reusing the verified claims role in account pages, and starting independent checkout policy reads early. Exact admin order-number routes are revalidated after relevant payment, fulfillment, email, and entitlement mutations.

Public catalog and product pages remain `force-static` with `revalidate = 300`; their metadata, JSON-LD, localized URLs, and private market projection boundaries were not changed.

## Intentionally deferred

- Cart quantity optimism remains server-authoritative because quote, inventory, market, and reservation reconciliation require a separate commerce design.
- Product review streaming remains unchanged because aggregate review JSON-LD and visible review content must stay consistent for SEO.
