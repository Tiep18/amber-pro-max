# Quick Task 260727-v05: Safe loading and perceived-performance improvements

## Scope boundaries

- Do not change cart quote, checkout pricing, inventory reservation, payment transition, entitlement authorization, fulfillment state-machine, or market-resolution logic.
- Do not add request data to public static catalog/product rendering.
- Do not remove or weaken `dynamic = 'force-static'`, `revalidate = 300`, metadata, JSON-LD, canonical, alternate-language, or market-safe projection behavior.
- Do not implement cart-wide optimistic quantity changes or stream product reviews in this task; both require separate commerce/SEO design work.

**Action**

- Build neutral skeletons from the existing `Skeleton` primitive and current layout tokens.
- Preserve localized header/footer and admin chrome by placing fallbacks below existing layouts.
- Match major page geometry to avoid layout shift, but never render placeholder prices, stock, payment status, or actionable controls.
- Include an accessible bilingual pending announcement without making the fallback a client component.

**Verify**

- Every audited dynamic/slow segment has a nearest loading boundary.
- Loading components import no cookies, headers, Supabase clients, market context, or commerce data.
- Public page `dynamic`, `revalidate`, metadata, and JSON-LD declarations remain unchanged.

**Done**

- Navigation has immediate visual feedback with stable layout and no change to route authority or cache classification.

- `src/components/admin/orders/vietqr-evidence-form.tsx`
- `src/components/admin/taxonomy/taxonomy-manager.tsx`

**Action**

- Add pending labels and duplicate-submit protection only to the initiating form/control.
- Use App Router transitions for navigation and `router.refresh()` so busy state ends when the destination tree commits, not after a fixed timer.
- Keep both mutually exclusive VietQR decisions locked while either is running.
- Scope address and wishlist states to the affected item.
- Consume guest-order claim results and route a successful claim to the authenticated order page.
- Add checkout `try/catch/finally` without automatic resubmission; retain the existing idempotency key and let the customer explicitly retry.
- Revalidate the exact admin order-number route after payment/fulfillment mutations in addition to the queue.

**Verify**

- No payment/order action is automatically retried.
- PayPal cooldown remains throttling-only and does not define completion.
- Protected downloads continue to POST to the server-owned authorization route and never expose signed URLs to client state.
- Mutually exclusive or destructive controls cannot be submitted twice while pending.

**Done**

- Audited actions provide immediate, accurate, accessible feedback without changing server-side business decisions.
